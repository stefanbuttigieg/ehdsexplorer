# Agent rules

- Two-step verification uses native TOTP or server-only, keyed, session/purpose-bound email challenges consumed atomically; restrictive RLS and authenticated edge actions check the server-owned verified session, never browser flags — prevents password-only bypass and code replay without changing public reads.

- Implementation updates use configured research and official country sources; only exact, recent, obligation-specific official evidence can auto-publish, with atomic evidence/status writes and optimistic conflict detection — prevents AI inference or stale checks from overwriting reviewed progress.
- Scheduled implementation checks rotate one source daily and persist provider pauses; cron authentication uses a private service-only settings token — bounds recurring costs and prevents anonymous writes.

- Country maps keep the shared Leaflet renderer and key-free OpenStreetMap standard tiles with visible attribution — avoids provider API-key prompts across classic, beta, and Kids Mode.

- Committee meeting previews sort distinct meeting records by meeting date before limiting display; never sort by cache creation time or infer totals from ordinal titles — keeps the newest meetings visible and counts accurate.
- Committee refreshes use the official register JSON feed and follow all returned pages, rejecting incomplete retrieval or failed storage — avoids silently reporting a partial scrape as current.

- MCP server tools live in src/lib/mcp (one defineTool per file, registered in index.ts) and use OAuth caller-scoped Supabase clients; supabase/functions/mcp is generated by mcpPlugin, never hand-edited — keeps RLS and identity enforced.
- MCP FAQ search includes rich_content and resolves answers with rich content preferred over legacy answer, matching the website — prevents missing or stale answers without duplicating source data.
- The dedicated Cloudflare MCP proxy in scripts/cloudflare forwards only fixed MCP/discovery paths, streams caller-authenticated traffic, and rewrites resource discovery without changing the authorization issuer; update the guide and canonical server resource only after proxy deployment is verified — prevents open forwarding and premature connection URLs.
- Optional beta presentation is selected by BetaExperienceProvider at public home/search and Layout boundaries; canonical content routes and their loaders remain shared — preserves deep links and one search engine.
- Beta trials use session storage, adoption uses local storage, and switching back clears both; eligibility excludes Kids Mode and administrative/account/auth surfaces — avoids silent adoption and redirect loops.
- Beta search consumes useSearch and PopularTopicChips directly, with its own results presentation and scoped theme tokens — keeps search semantics and popularity safeguards consistent with classic.
- Beta choice events are sent only through the initialized consent-based PostHog provider on nonembedded production hosts; existing pageviews carry experience/default/environment labels — measures uptake without draft inflation or a second tracker.
